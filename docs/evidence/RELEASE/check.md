# Репетиция выпуска · 20 ноября 2026 года

Проверена версия bd5245b на Linux с Python 3.12, Django 5.2.19 и отдельной PostgreSQL 16.2. Хостинг и публичный адрес пока не выбраны. Настройки реального прокси, секретов провайдера, TLS к БД и постоянного хранилища предстоит проверить на площадке.

| Предмет проверки | Выполнено и получено |
|---|---|
| Настройки production | В процессе явно задан DJANGO_SETTINGS_MODULE=config.settings.production, включая команды manage.py. DEBUG выключен, список хостов требует конкретных имён. Включены HTTPS-редирект, Secure для сессии и CSRF, HttpOnly для сессии. Доверие к X-Forwarded-Proto требует единственного доверенного прокси, который перезаписывает заголовок. |
| Секреты | Для проверки ключ Django, пароли базы и двух студентов генерировались временно. Production-ключ и реквизиты PostgreSQL читаются из окружения через required(). В Git отслеживается шаблон .env.example с пустыми значениями. Проверка git check-ignore подтвердила исключение .env и .env.production. На хостинге постоянные значения задаёт капитан через хранилище секретов. |
| Диагностика | python manage.py check --deploy завершилась с кодом 0 и двумя предупреждениями HSTS — W005 (поддомены) и W021 (preload). Текущая политика HSTS — один час для выбранного хоста. Решение о расширении принимает владелец домена. |
| Статика | python manage.py collectstatic --noinput собрала cabinet.css и academic.css. Содержимое обеих копий совпало с исходными файлами. В публичном выпуске их обслуживает WhiteNoise. |
| Миграции и БД | Первая чистая копия исходников применила системные миграции и cabinet.0001–0002. При повторном migrate во второй копии результат — No migrations to apply. Обе команды migrate --check завершились успешно. Локальное подключение шло по закрытому Unix-сокету. Для сетевой БД конфигурация по умолчанию использует sslmode=require. |
| Заявка после повторного развёртывания | После seed_demo авторизованный клиент Django с включённой проверкой CSRF отправил форму справки. Сервер вернул /requests/3/. PostgreSQL остановили и запустили с тем же каталогом данных. Во второй чистой копии из того же git archive повторили collectstatic, migrate и seed_demo. В новом сеансе А карточка № 3 вернула HTTP 200 со статусом «Принята», номер остался в списке. Всего три записи, включая две исходные. |

Эта проверка воспроизводит замену файлов приложения и перезапуск локальной БД. Предыдущая приёмка дополнительно проверяла вход из Chromium через локальный HTTPS/Gunicorn, выдачу статики и сохранность восьми новых заявок после перезапуска. [Протокол QA](../QA/README.md)
