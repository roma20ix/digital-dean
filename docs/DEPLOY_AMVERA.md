# Публикация на Amvera: памятка капитану

Эта инструкция рассчитана на один проект Django и одну отдельную PostgreSQL в одном регионе Amvera. Пока публичный адрес не проверен командой, сайт не считается опубликованным. Публикацию и оплату выполняет капитан или участник с отдельным разрешением.

## 1. Подготовьте код

Сейчас файлы подготовки находятся в ветке `design/student-workspace`. В локальном клоне выполните `git fetch origin`, `git switch design/student-workspace`, `git pull --ff-only origin design/student-workspace`. Убедитесь, что в корне есть `amvera.yml`, а в `scripts/` — `start_amvera.sh`. Когда проверенная версия будет слита в `main`, можно переключить источник публикации на `main`. Позже для каждого обновления повторяйте `git pull` и отправляйте новый коммит в Amvera; базу не пересоздавайте.

## 2. Создайте PostgreSQL

1. Зарегистрируйтесь и войдите на <https://cloud.amvera.ru/projects>. Пополните баланс с запасом до конца 28 ноября по Москве. Текущую стоимость и условия тарифа проверьте в панели перед оплатой.
2. На главной выберите **PostgreSQL → Создать базу данных**. Укажите регион **Москва** (тот же, что будет у приложения), тариф **Стартовый**, имя проекта, например `dean-db`.
3. В форме БД укажите отдельные **имя базы** (`dean_db`), **имя пользователя** (`dean_user`) и сильный **пароль пользователя**. Не используйте зарезервированные имена `postgres`. Выберите **одну реплику**. Доступ суперпользователя для приложения не нужен.
4. Дождитесь статуса **PostgreSQL запущен**. Во вкладке **Домены** скопируйте внутренний адрес **для чтения и записи**, оканчивающийся на `-rw`. Не создавайте публичный домен для БД. Сохраните имя базы, пользователя и пароль в менеджере паролей, не в Git.
5. Включите ежедневные резервные копии, если переключатель доступен на выбранном тарифе.

## 3. Создайте приложение

1. Вернитесь к списку проектов, нажмите **Создать**, выберите **Приложение** и **тот же регион Москва**.
2. Назовите проект, например `digital-dean`. Выберите тариф **Начальный Плюс (1 ГБ RAM)**. Для Django на 8 дней это надёжнее тарифа на 0,1 ГБ.
3. На шаге загрузки кода пока нажмите **Отмена/Пропустить**. Файл конфигурации уже лежит в нашем репозитории; не генерируйте другой `amvera.yml` в панели.
4. Во вкладке **Домены** приложения включите бесплатный HTTPS-домен и скопируйте его адрес. В `DJANGO_ALLOWED_HOSTS` ниже нужен только хост, **без** `https://` и завершающего `/`.

## 4. Заполните «Переменные» приложения

Откройте проект приложения → **Переменные** → **Добавить переменные или секрет**. Имена в таблице вводите точно. Значения паролей выбирает капитан; `.env` из компьютера в Amvera не загружается. После изменения переменных контейнер надо перезапустить.

| Имя | Тип | Что ввести |
|---|---|---|
| `DJANGO_SECRET_KEY` | секрет | Постоянный случайный ключ, например 64 шестнадцатеричных символа |
| `DJANGO_ALLOWED_HOSTS` | переменная | Хост бесплатного домена приложения без схемы |
| `PGDATABASE` | переменная | Имя созданной базы, например `dean_db` |
| `PGUSER` | переменная | Пользователь БД, например `dean_user` |
| `PGPASSWORD` | секрет | Пароль пользователя БД |
| `PGHOST` | переменная | Внутренний адрес БД из вкладки «Домены», заканчивается на `-rw` |
| `PGPORT` | переменная | `5432` |
| `PGSSLMODE` | переменная | `disable` только для внутренней сети Amvera |
| `DEMO_STUDENT_A_PASSWORD` | секрет | Отдельный пароль студента А |
| `DEMO_STUDENT_B_PASSWORD` | секрет | Другой пароль студента Б |
| `DEMO_TEACHER_PASSWORD` | секрет, необязательно | Третий отдельный пароль для `teacher_a` |

Сильный ключ и пароли можно генерировать в личном PowerShell командой `py -3.12 -c "import secrets; print(secrets.token_hex(32))"`, каждый раз заново. Ключ Django и пароли БД/студентов должны различаться. Сохраните их вне репозитория. `DJANGO_SETTINGS_MODULE` уже установлен в `scripts/start_amvera.sh`; `DEBUG` в production равен `False`. `PORT` задавать не надо: `amvera.yml` и Gunicorn слушают порт 80.

## 5. Передайте код в Amvera

В проекте приложения откройте вкладку **Репозиторий** и скопируйте HTTPS-адрес репозитория Amvera. В PowerShell, в локальной папке `digital-dean`, один раз выполните:

```powershell
git remote add amvera <скопированный HTTPS-адрес>
git push amvera HEAD:master
```

Вставляйте настоящий адрес вместо текста в угловых скобках. Если `amvera` уже добавлен, повторно добавлять его не нужно: проверьте `git remote -v`. Для обновления опубликованной ветки выполните:

```powershell
git pull --ff-only origin design/student-workspace
git push amvera HEAD:master
```

После слияния проверенной ветки в `main` можно выполнить `git switch main`, `git pull --ff-only origin main`, затем `git push amvera HEAD:master`. Перед этой сменой убедитесь, что новая `main` содержит опубликованные изменения и `amvera.yml`.

Amvera установит зависимости из `requirements.txt`, затем `start_amvera.sh` соберёт статику, применит миграции, подготовит демоаккаунты и запустит Gunicorn. Эти команды безопасно повторяются при обновлении приложения. Не используйте `runserver` для публикации.

## 6. Проверьте результат

1. В панели проверьте статусы **Сборка** и **Приложение**. Если возникла ошибка, откройте логи и запишите первую содержательную строку ошибки без паролей.
2. Откройте `https://<домен>/health/`: ответ должен быть `ok`. Затем `https://<домен>/login/`. Проверьте CSS и вход под `student_a` и `student_b` с заданными разными паролями. Если задан пароль преподавателя, проверьте `teacher_a`.
3. Под `student_a` создайте справку и запишите её номер. Выполните повторный `git push amvera HEAD:master` или перезапуск приложения **с той же PostgreSQL**. В новом сеансе войдите снова и проверьте тот же номер и статус заявки.
4. Впишите проверенный адрес и коммит в `docs/SUBMISSION.md`. Капитан передаёт реальные пароли только в закрытом комментарии организатора.
5. Лично проверьте сайт на российском мобильном интернете без VPN, а ссылки на сайт, исходники и отчёт — в приватном окне. Проверьте в панели достаточность баланса до конца 28 ноября по Москве и фактическое время закрытия приёма у организатора.
