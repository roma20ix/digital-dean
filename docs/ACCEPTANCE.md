# Приёмка глазами жюри

Для каждого пункта допишите дату проверки, среду, коммит, фактический результат и ссылку на материал. Эта таблица перечисляет ожидаемые результаты будущей проверки.

| Проверка | Что должен увидеть проверяющий |
|---|---|
| 01. Доступ | Публичный HTTPS-адрес открывается с мобильного интернета и другой российской сети без VPN, без входа в GitHub или ChatGPT. Стили и иконки тоже загрузились. |
| 02. Два входа | Два тестовых студента входят разными логинами и паролями. В профиле у каждого свои ФИО, факультет, направление, курс и группа. Неверный пароль даёт понятную ошибку. |
| 03. Расписание | «Сегодня» и «Неделя» согласованы. Видны предмет, время, аудитория и преподаватель. При переносе видны прежнее и новое место. Уведомление открывает нужное занятие. |
| 04. Учёба | Есть оценки по дисциплинам, зачёты и экзамены с датами. Оценка, зачёт и ещё не выставленный результат различимы текстом. |
| 05. Справка | Со стартовой страницы студент открывает форму, отправляет один раз, видит номер и статус. Двойное нажатие не создаёт дубликат. После выхода и повторного входа у заявки тот же номер. |
| 06. Обращение и объявления | Студент может отправить обращение в деканат. Видит новости, напоминания о сроках и изменения. Прочтение новости одним студентом не меняет состояние для второго. |
| 07. Границы доступа | На тестовых фикстурах подтверждены закрытость кабинета до входа, разделение профилей, персональных оценок, заявок, сообщений и доступа по прямой ссылке. Ранее открытая закрытая страница при новом запросе после выхода требует входа. |
| 08. Первое впечатление | На 360 px можно пройти вход, перенос, оценку и справку. Нет боковой прокрутки. Проверены длинный заголовок, пустой день, ошибка ввода, фокус, читаемость текста и понятное состояние после нажатия «Отправить». |
| 09. Повторное развёртывание | После перезапуска опубликованного приложения сохранена созданная заявка. Повторная инициализация демо не стирает пользовательские записи и не плодит занятия. |
| 10. Честный концепт | Видна пометка о конкурсе и вымышленных данных. Свой логотип или текстовый знак. Для стороннего кода, иконок, шрифтов и картинок есть источник и допустимая лицензия. |
| 11. Выдача жюри | В приватном окне доступны сайт, исходный код или архив, PDF/документ со снимками и при наличии видео до 5 минут. В комментарии есть 2 рабочих студенческих доступа. Учётка сотрудника нужна только при отдельном кабинете сотрудника. |
| 12. Срок | Проверены фактический дедлайн подачи, отправка капитаном, баланс/период работы сайта и БД включительно по 28 ноября, отсутствие остановки демо по неактивности либо приемлемое и проверенное время первого открытия. |

## Маршрут на телефон, 90 секунд

1. Войти студентом A. Показать персональную главную и перенос. Открыть занятие и назвать новую аудиторию.
2. Открыть «Учёба», найти ближайший экзамен и зачёт. Вернуться на главную.
3. Заказать справку, увидеть номер, открыть её из «Мои заявки».
4. Завершить сеанс. Войти студентом Б, показать другой профиль, оценки и иной список заявок. Вернуться в аккаунт A и открыть свою созданную заявку.
5. Сложные проверки доступа и сохранности привязать к отчёту о тестах. Отдельно заснять реальный мобильный экран.

## Заготовка комментария капитана

Прототип: <публичный HTTPS-адрес>
Студент А: <логин> / <демопароль>
Студент Б: <логин> / <другой демопароль>
Исходный код: <ссылка с доступом для жюри>
Описание процесса: <документ или PDF со скриншотами>
Видео (если готово): <ссылка>
Начните с «Сегодня»: откройте сообщение о переносе. Затем закажите справку и сверьте историю двух студентов.

Заполненный комментарий с паролями передаётся в личном кабинете конкурса. Хостинговые и административные пароли для жюри не требуются.
