# Деканат · старт для команды из двух человек

Это рабочий комплект инструкций. Приложение, продакшен-доступы и конкурсный отчёт появятся в ходе разработки.

## Первые 30 минут

1. Уточните в личном кабинете организатора дату и время окончания приёма работ. 28 ноября в задании обозначено как день объявления итогов. Запишите свой внутренний срок на день раньше фактического дедлайна, если он это позволяет.
2. Капитан создаёт на GitHub личный репозиторий `digital-dean` с README и веткой `main`. В Settings → Collaborators → Add people приглашает второго участника. Друг принимает приглашение со своего GitHub. Для работы вдвоём подходит приватный репозиторий. К сдаче подготовьте публичный исходный код, доступ жюри или архив по открываемой ссылке.
3. Распакуйте этот ZIP. Капитан загружает в корень репозитория **содержимое** папки `digital-dean-kit` через Add file → Upload files. Файл `AGENTS.md` должен лежать рядом с README. Добавьте полный текст задания в `docs/BRIEF.md`, если хотите, чтобы участники видели оригинал. Закоммитьте стартовые документы.
4. Каждый входит в Codex под своим ChatGPT и даёт доступ к проекту через свой GitHub. При использовании облака выберите режим Cloud и один и тот же репозиторий. Владелец репозитория проверяет, что интеграции разрешён доступ к нему. Пусть оба по отдельности попросят: «Назови текущую ветку, последний коммит и прочитай первую строку AGENTS.md». Сверьте один и тот же стартовый коммит. Подписки и истории диалогов остаются индивидуальными.
5. В PROMPTS.md есть порядок выдачи заданий. Ровно один агент создаёт техническую основу. Второй в это же время делает черновик экрана и помогает проверить идею. Влейте основу в main. Дальше каждый запускает задачу из свежей main в собственной ветке. Если продолжаете старую облачную задачу, явно подтяните изменения из main и проверьте, что они доступны.
6. Для каждой задачи создайте GitHub Issue с владельцем, границами файлов и проверкой результата. Удобно назвать первые задачи «Основа проекта», «Мобильный эскиз», «A1. Вход и заявки», «B1. Сегодня и справка». Следующие уже перечислены в PROMPTS.md. Через Pull requests → New pull request сравните свою ветку с main, если Codex не предложил готовую кнопку создания PR. Проверьте изменения и только затем объедините ветки.

### Если один из вас работает в IDE

Каждый клонирует проект **в свою папку на своём компьютере**, открывает папку в редакторе с Codex и входит через свой ChatGPT. GitHub Desktop подойдёт для Clone repository, New branch, Publish branch и Create pull request. В терминале первый заход выглядит так (вместо OWNER подставьте GitHub-логин капитана):

```sh
git clone https://github.com/OWNER/digital-dean.git
cd digital-dean
git switch main
git pull --ff-only origin main
git switch -c feat/server-requests
```

Для участника Б имя ветки — `feat/ui-requests`. После проверок выберите в редакторе нужные файлы для коммита, проверьте список (без .env, дампов, паролей и истории сессий), сделайте коммит и выполните `git push -u origin HEAD`. Создайте PR в main. Каждую следующую независимую задачу начинайте от обновлённой main. Когда нужно проверить две незавершённые ветки вместе, один интегратор может собрать их в отдельной временной ветке через обычное слияние и прогнать тесты. Сначала объедините согласованные PR, затем повторите проверки на main.

## Кто за что отвечает

| Работа | Участник А | Участник Б |
|---|---|---|
| Первый час | Запуск Django, CI, БД, первая публикация /health/ | Разговоры с 2–3 студентами, если доступны. Два эскиза телефона, выбор одного |
| Первый рабочий цикл | Вход, выход, профиль, создание и хранение заявки | Вход, главный экран, форма справки, карточка и список заявок |
| Второй цикл | Расписание, перенос, успеваемость, сессия, уведомления и демоданные | Дневной и недельный виды, экран учёбы, сообщения, пустые состояния |
| Выпуск | Публикация, постоянная БД, учётки, резервная копия, доступ после перезапуска | Проверка на телефоне, портфолио скриншотов, PDF и короткое видео |
| На каждом слиянии | Ревью интерфейса и ручное прохождение | Ревью серверных проверок и повторение пути пользователя |

Договоритесь, кто интегратор на сегодня. Он следит за состоянием main, зависимостями, настройками деплоя и изменениями соглашения в docs/CONTRACT.md. На каждую функцию — один короткий PR. В завершение сообщите партнёру номер PR, базовый коммит, что можно проверить и что ещё зависит от другого PR. Удобно фиксировать это в Issue. Совместные решения переносите из личных чатов в репозиторий.

## Идея для показа

«Сегодня» отвечает на три разных вопроса: куда идти, что успеть и что стало с моей заявкой. Главная история — пара переехала из 304 в 218. Старое и новое место, время и источник сообщения видны сразу; одно нажатие открывает именно это занятие в расписании. Параллельная история — справка о том, что студент учится: заказать, увидеть номер и статус, вернуться к заявке после выхода. Для второго студента подготовьте другой профиль, группу, набор оценок и историю заявок.

## План от фактического дедлайна

- Первая совместная сессия. Получите хотя бы один доступный по HTTPS тестовый адрес. В конце вечера оба участника должны уметь войти и пройти путь «заказать справку → увидеть её после повторного входа».
- Следующая сессия. Закройте пять обязательных разделов. Проверьте с телефона, что перенесённая пара и заявка открываются из «Сегодня». Добавьте собственную идею только после этой проверки.
- За день до закрытия приёма, если график позволяет. Заморозьте новые функции. Соберите PDF и ссылки. Дайте одному человеку пройти маршрут без подсказок. При нехватке времени вычеркните видео или декоративную анимацию.
- До отправки. Капитан открывает все ссылки в приватном окне, проверяет работу с двух российских сетей без VPN, время сдачи и запас действия хостинга как минимум до конца 28 ноября по МСК.
